# آزمایش TCP با EZCAD2

پروژه مستقل Python 3.10+، بدون پکیج اضافی. پوشه را می‌توانید به هر مسیر دلخواه منتقل و در VS Code باز کنید. هیچ وابستگی به XYPrinter ندارد. این برنامه فقط به درخواست TCP پاسخ می‌دهد؛ فایل EZCAD2 را تغییر نمی‌دهد و فرمان مارکینگ یا کنترل لیزر ندارد.

## ۱. اجرای محلی بدون دستگاه

در VS Code گزینه Open Folder را روی همین پوشه انتخاب کنید. در ترمینال PowerShell:

```powershell
python --version
python server.py --host 127.0.0.1
```

در ترمینال دوم، از همین پوشه:

```powershell
python client.py
```

باید `PASS` و پاسخ `A1B2` با HEX برابر `41 31 42 32` دیده شود. کلاینت با کد خروج ۰ موفقیت و با ۱ شکست را اعلام می‌کند. در ترمینال سرور بنویسید:

```text
/set C3D4
/show
```

سپس در ترمینال دوم:

```powershell
python client.py --expect C3D4
```

نوشتن متن معمولی نیز پاسخ را تغییر می‌دهد. `/quit` یا Ctrl+C سرور را متوقف می‌کند؛ بسته‌شدن ورودی کنسول نیز برنامه را متوقف می‌کند. پاسخ در حافظه است و پس از اجرای مجدد به مقدار پیش‌فرض برمی‌گردد. فعلاً فقط ASCII پذیرفته می‌شود؛ Unicode غیرفعال در EZCAD2 به‌تنهایی نوع کدگذاری متن غیرلاتین را مشخص نمی‌کند.

## ۲. شبکه محلی

روی کامپیوتر سرور دستور زیر را اجرا کنید:

```powershell
ipconfig
```

IPv4 آداپتور فعال Wi-Fi یا Ethernet متصل به شبکه مشترک را انتخاب کنید؛ IP نمونه `192.168.0.1`، Default Gateway، آدرس VPN یا `127.0.0.1` را جایگزین IP واقعی نکنید. سپس سرور محلی قبلی را متوقف کنید و اجرا کنید:

```powershell
python server.py --host 0.0.0.0 --port 1000
```

`0.0.0.0` یعنی گوش‌دادن روی تمام رابط‌ها؛ در EZCAD2 باید IPv4 واقعی سرور وارد شود. برای محدودکردن رابط می‌توانید همان IPv4 را به `--host` بدهید.

اگر Windows Firewall ارتباط را مسدود می‌کند، برای شبکه مورداعتماد با پروفایل Private، در PowerShell دارای دسترسی Administrator این قانون محدود به شبکه محلی را ایجاد کنید:

```powershell
New-NetFirewallRule -DisplayName "EZCAD2 TCP Test 1000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 1000 -Profile Private -RemoteAddress LocalSubnet
```

این فرمان خودکار اجرا نمی‌شود. فایروال را خاموش نکنید. پس از پایان آزمایش می‌توانید قانون را حذف کنید:

```powershell
Remove-NetFirewallRule -DisplayName "EZCAD2 TCP Test 1000"
```

روی کامپیوتر EZCAD2، IP واقعی سرور را جایگزین مقدار داخل گیومه کنید:

```powershell
Test-NetConnection -ComputerName "SERVER_IP" -Port 1000
python client.py --host "SERVER_IP"
```

برای دستور دوم فایل client.py و Python روی آن کامپیوتر لازم است. تست اول فقط اتصال را بررسی می‌کند و چون متنی نمی‌فرستد، ممکن است در لاگ سرور قطع اتصال یا timeout دیده شود. هر دو کامپیوتر باید مسیر شبکه به هم داشته باشند؛ شبکه مهمان و AP isolation ممکن است ارتباط را مسدود کنند.

## ۳. آزمون دریافت در EZCAD2، بدون مارکینگ

در Text Element گزینه `TCP/IP iletişim` را انتخاب کنید:

- IP Address: IPv4 واقعی کامپیوتر سرور
- Port: `1000`
- Command: `TCP:Give me string`
- Unicode: غیرفعال

پاسخ سرور را به `/set A1B2` برگردانید. فقط از عملیات شناخته‌شده و بدون مارکینگ برای به‌روزرسانی متن استفاده کنید؛ Mark، F2، تریگر خارجی یا پدال را برای ایجاد درخواست امتحان نکنید. اگر نسخه نصب‌شده تنها هنگام Mark درخواست می‌فرستد، همین مرحله را متوقف و این محدودیت را ثبت کنید؛ این پروژه مجوز فعال‌کردن لیزر نیست.

معیار موفقیت واقعی: اتصال EZCAD2 در لاگ، ثبت بایت‌های درخواست، ارسال `41 31 42 32`، و مشاهده جایگزینی `A1B2` در طرح. موفقیت کلاینت شبیه‌ساز یا ثبت TX به‌تنهایی اثبات دریافت در EZCAD2 یا موفقیت مارکینگ نیست.

## ۴. آزمایش فرض‌های پروتکل

نقش TCP Client برای EZCAD2 هنوز فرض است. سرور هیچ فرمان خاصی را الزام نمی‌کند و به هر درخواست کامل تشخیص‌داده‌شده پاسخ می‌دهد. همه قطعات دریافتی با timestamp، IP/port، تعداد بایت، متن escape‌شده و HEX در کنسول و `logs/server.log` ثبت می‌شوند. فایل‌ها چرخشی‌اند: فایل فعال و حداکثر پنج نسخه ۵ مگابایتی؛ برای نگهداری بلندمدت قبل از بازنویسی کپی کنید.

TCP جریان بایت است و یک recv الزاماً یک پیام نیست. پیش‌فرض، داده‌ها را تا ۲۰۰ میلی‌ثانیه سکوت جمع می‌کند، پاسخ خام می‌دهد و اتصال را می‌بندد. این تشخیص تجربی ممکن است در شبکه کند پیام را زود جدا کند یا چند درخواست را یکی ببیند. timeout کلی درخواست پیش‌فرض ۱۰ ثانیه و سقف بافر ۶۴ کیلوبایت است. هر اتصال مستقل پردازش می‌شود؛ این ابزار آزمایشی برای LAN مورداعتماد است، نه سرویس عمومی تولید.

هر بار فقط یک متغیر را تغییر دهید و نتیجه را ثبت کنید:

```powershell
python server.py --ending crlf
python server.py --ending null
python server.py --gap 0.5
python server.py --keep-open
```

گزینه `--ending` مقادیر `none`, `crlf`, `lf`, `null` دارد. اگر HEX درخواست پایان مشخصی را نشان داد، مرز درخواست را صریح تعیین کنید:

```powershell
python server.py --request-ending crlf --keep-open
```

در این حالت فقط پیام دارای CR/LF پاسخ می‌گیرد؛ پیام ناقص هنگام timeout رد می‌شود. چند درخواست در اتصال پایدار پشتیبانی می‌شوند. کلاینت دستی برای حالت پیش‌فرض بسته‌شدن اتصال طراحی شده است و با `--keep-open` timeout خواهد داد؛ آزمون اتصال پایدار در تست‌های خودکار پوشش داده شده است. برای تست پایان پاسخ، گزینه‌های متناظر کلاینت را تنظیم کنید، مثلاً `python client.py --ending crlf`.

برای هر آزمایش نسخه EZCAD2، عملیات UI، زمان، RX HEX، TX HEX، وضعیت اتصال و متن مشاهده‌شده را ثبت کنید. هنوز مشخص نیست درخواست هنگام به‌روزرسانی ارسال می‌شود یا Mark، فرمان دقیق چیست و چه پایان پاسخی لازم است. هیچ نتیجه‌ای از مستندات عمومی به نسخه نصب‌شده تعمیم داده نشده است.

## ۵. عیب‌یابی و تست

- خطای bind یا WinError 10048: برنامه دیگری پورت را اشغال کرده؛ نمونه تکراری سرور را ببندید.
- عدم اتصال: IP، پروفایل فایروال، پورت و جداسازی شبکه Wi-Fi را بررسی کنید.
- اتصال بدون RX: کلاینت متنی نفرستاده یا عملیات EZCAD2 درخواست ایجاد نکرده است.
- RX و TX بدون جایگزینی: پایان پیام، encoding و تنظیمات Text Element هنوز نیازمند بررسی‌اند.
- timeout یک اتصال، سرور را متوقف نمی‌کند؛ اتصال جدید می‌تواند ادامه دهد.

اجرای تست‌های خودکار فقط روی loopback و پورت موقت:

```powershell
python -m unittest -v
```

توسعه صف سریال، دیتابیس، مصرف شماره و تأیید مارکینگ خارج از این مرحله است. هیچ شماره‌ای صرفاً با ارسال پاسخ مصرف‌شده محسوب نمی‌شود.
